IRIS DATE : Site de rencontre étudiant (PHP & MySQL)

Conception et réalisation d'une application web dynamique complète mettant en œuvre le modèle CRUD, l'extension mysqli avec requêtes préparées, et le téléversement de photos de profil.

1. Contexte & Objectifs du projet

Dans le cadre de ma formation en BTS SIO à l'école IRIS, j'ai développé IRIS DATE, une plateforme web dynamique destinée aux étudiants. Ce projet a pour but de consolider la conception et le développement d'une application web connectée à une base de données relationnelle.

Le site permet aux étudiants de s'inscrire avec un pseudo et une photo de profil, de visualiser la liste complète des membres enregistrés, d'éditer leur profil et de supprimer un compte. Ces actions couvrent l'intégralité du cycle CRUD (Create, Read, Update, Delete) fondamental en ingénierie logicielle.

2. Organisation du code & Arborescence

L'application est hébergée sur un environnement local Apache/PHP/MySQL et s'articule autour des composants suivants :

iris_date/ ├── bdd.sql → Script SQL de création de la BDD et insertion des données de test ├── index.php → Accueil : liste des membres, formulaire d'inscription et suppression ├── profil.php → Formulaire de modification complète d'un profil membre ├── style.css → Feuille de style CSS └── images/ → Répertoire de stockage des photos téléversées et icônes d'action ├── modifier.png └── supprimer.png
Action utilisateur Page Traitement PHP Requête SQL
Consulter les membres (Read) index.php Parcours des résultats en boucle HTML SELECT * FROM user
Inscription + photo (Create) index.php Upload sécurisé avec move_uploaded_file() INSERT INTO user ...
Suppression de compte (Delete) index.php?action=suppr&id=... Récupération de l'identifiant et suppression DELETE FROM user WHERE iduser=?
Modification profil (Update) profil.php?action=modif&id=... Pré-remplissage dynamique et mise à jour UPDATE user SET ... WHERE iduser=?
3. Modélisation de la base de données (MySQL)

La base relationnelle iris_date est modélisée avec deux tables principales reliées par clés étrangères :

  • Table user : Stocke les coordonnées, identifiants, bio, genre et le chemin d'accès relatif vers la photo (seul le chemin est en BDD, le fichier binaire réside sur le disque serveur).
  • Table message : Conçue pour la messagerie inter-étudiants, reliant l'expéditeur (iduser1) et le destinataire (iduser2) via deux contraintes de clés étrangères (Foreign Keys).
CREATE TABLE message ( iduser1 INT, iduser2 INT, msg VARCHAR(2000), CONSTRAINT fk_user1 FOREIGN KEY(iduser1) REFERENCES user(iduser), CONSTRAINT fk_user2 FOREIGN KEY(iduser2) REFERENCES user(iduser) );
4. Fonctionnalités & Sécurité des requêtes
  • 1
    Protection contre les injections SQL : Utilisation systématique des requêtes préparées avec l'objet mysqli (prepare(), bind_param() avec typage strict s et i, puis execute()).
  • 2
    Gestion de l'upload d'images : Formulaire avec enctype="multipart/form-data", création automatique du dossier de destination avec mkdir() et transfert sécurisé via move_uploaded_file().
  • 3
    Formulaires dynamiques pré-remplis : Utilisation de l'opérateur ternaire pour injecter les données existantes du profil dans les champs du formulaire lors d'une modification.
5. Bilan & Pistes d'amélioration de sécurité

Dans une démarche d'analyse critique du code développé, plusieurs axes d'évolution ont été consignés dans le bilan technique :

  • Hachage des mots de passe : Implémentation de password_hash() (Argon2id ou Bcrypt) pour remplacer le stockage en clair.
  • Protection XSS : Échappement systématique des données utilisateur affichées avec htmlspecialchars().
  • Validation de l'upload : Vérification de l'extension et du type MIME réel de l'image (éviter tout script malveillant).
  • Gestion de sessions : Implémentation d'une authentification avec variables $_SESSION.
